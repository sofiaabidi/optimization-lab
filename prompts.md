## Zero-waste workflow

1. In VS Code open the repository **root**; use Codex with repository access. Keep `plan.md` and this file in root. Paste the **entire** requested prompt, not the entire repository context. The prompt directs Codex to read only relevant files.
2. Let Codex edit files and run the bounded checks named in that prompt. Inspect its brief completion summary; proceed if the acceptance gate passes. Fix only genuine blockers or incorrect outcomes, not cosmetic imperfections.
3. Save **original prompt + real AI response/excerpt + actual revision or “none” + verification results + commit hash + screenshot/export** under `prompts/<track>/`. Codex may create a log *template*, but only you can supply the real transcript/screenshot. Log all AI tools including ChatGPT planning and any debugging assistant.
4. Commit after each successful gate. Use `[AI:Codex] ...` for changes substantially generated by Codex; `[MANUAL] ...` for your own edits. Never fake failure cases or use Codex to invent its own tool metadata.
5. If an external dependency blocks the task, Codex must report **exact install/re-run instructions and BLOCKED status**, not silently substitute a mock result.

**Common execution rules (apply to every prompt):**
- Follow `plan.md`, assignment deliverables and relevant code; no frontend, no vague architecture detours, no unnecessary scaffolding. Use clear, maintainable, modest code and fixed seeds.
- Each track must document mathematical problem/objective, variables, constraints, baseline, selected alternatives, reasons, correctness oracle, data/hardware/seed, actual results and limitations. Save genuine raw result CSV/JSON and reproducible commands; plot only collected data.
- Use existing shared helpers; avoid duplicating work. Add focused tests, run them once after the change, and report actual pass/fail. More checks only when a failure or safety issue requires it (xv6 is the exception: test each kernel change).
- Never assert a command was executed if it wasn't; never invent benchmark numbers, Git commit URLs, model names, failed AI prompts, chat exports or screenshots. Separate `NOT RUN`, `BLOCKED`, and `FAILED`.
- Don't repeatedly re-read the entire repository or run expensive full suites. Read necessary files, implement, validate, summarize in **≤12 lines**: files changed, commands/results, limitations, git status, next step.
- If task is too large for one response, **finish a coherent vertical slice and list the exact remaining acceptance items**; don't claim whole-track completion.
