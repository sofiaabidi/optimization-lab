# H — SQLite storage-budgeted index selection

Status: **real SQLite quick profile executed** on 2026-10-29. The full scale profile is **NOT RUN**.

## Decision problem

Given six candidate indexes and storage budget `B = 2,500,000` bytes, select an index set that minimizes measured weighted warm-query latency. The workload weights are operational frequencies, not optimizer-estimated costs.

For interaction-aware exact optimization, each of the 64 complete subsets `S` is built and measured on a fresh baseline database copy. Binary `z_S` selects one measured subset:

```text
minimize   sum_S measured_latency(S) z_S
subject to sum_S z_S = 1
           sum_S measured_storage(S) z_S <= B
           z_S in {0, 1}
```

Candidate-level decisions are `x_i = sum_{S containing i} z_S`. This one-hot ILP retains arbitrary latency and page-allocation interactions instead of assuming individual index benefits are additive. SciPy/HiGHS solves the binary model and an exhaustive feasible-subset oracle independently verifies its objective. Conditional greedy starts with no indexes and repeatedly adds the feasible index with the largest newly measured benefit per incremental byte; it also uses the current complete subset rather than fixed standalone benefits.

## Dataset and workload

The deterministic seed-2026 campus database contains 12 departments, 240 courses, 10,000 synthetic students, and 60,000 enrollments across four terms. No personal or production data are used. Foreign keys and realistic status, campus, advisor, term, grade, and course relationships are generated by documented formulas. The no-added-index baseline is 2,842,624 bytes and retains only SQLite's schema-created primary-key/unique indexes.

Five parameterized query templates have three cases each:

| Query | Weight | Purpose |
|---|---:|---|
| Student history | 30 | A student's courses and grades in one term |
| Course roster | 25 | Students and grades for one course/term |
| Advisor active students | 20 | Active advisees ordered by name |
| Department term GPA | 15 | Per-course enrollment and average grade |
| Campus at-risk | 10 | Low-grade aggregation for one campus/term |

The six composite candidates cover student/term and course/term enrollment access, advisor/status lookup, department courses, risk filtering, and campus filtering. Their exact DDL is in [`dataset_manifest.json`](../../results/h/dataset_manifest.json).

Standalone measurements demonstrate their different costs and benefits; selection itself uses complete-subset measurements:

| Candidate | Added bytes | Weighted latency alone | Improvement vs default |
|---|---:|---:|---:|
| Enrollment student/term | 1,650,688 | 183.272 ms | 33.6% |
| Enrollment course/term | 1,650,688 | 39.091 ms | 85.8% |
| Student advisor/status | 299,008 | 267.938 ms | 2.9% |
| Course department | 4,096 | 257.658 ms | 6.6% |
| Enrollment risk | 1,499,136 | 239.499 ms | 13.2% |
| Student campus | 172,032 | 231.985 ms | 15.9% |

Each of 64 subsets uses a fresh database copy, `ANALYZE`, one untimed warmup per query case, and five timed executions per case. Database generation, index build, and query time are separated. `PRAGMA journal_mode=DELETE`, `synchronous=OFF`, a 20 MB SQLite cache, and `automatic_index=ON` are fixed. The durability setting is suitable only for this disposable read benchmark.

## Measured results

| Strategy | Added indexes | Storage | Build | Weighted latency | Actual single-client throughput |
|---|---|---:|---:|---:|---:|
| SQLite default | none | 0 | 0 | 275.892 ms | 405.7 queries/s |
| Conditional greedy | course-department, enrollment-course-term, student-advisor-status | 1,953,792 B | 43.64 ms | 30.603 ms | 2,691.3 queries/s |
| Exact measured-subset ILP | same three indexes | 1,953,792 B | 43.64 ms | 30.603 ms | 2,691.3 queries/s |

The selected set reduced the weighted latency objective by 88.9% and changed all 15 parameter-case plans while staying 546,208 bytes under budget. In this run greedy reached the exact optimum, so ILP produced **no additional improvement**. Actual throughput is the median of three separately timed 100-query weighted streams after warmup; because both methods selected the same physical indexes, that configuration was measured once and the same rate is reported for both.

Representative plan changes include:

- Course roster: `SCAN enrollments` became `SEARCH ... USING COVERING INDEX idx_enrollment_course_term (course_id=? AND term=?)`.
- Advisor query: `SCAN students` plus a temporary order B-tree became a direct search through `idx_student_advisor_status`.
- Department GPA: the baseline enrollment scan became searches through both the course-department and enrollment-course-term covering indexes.

Pair measurements are visibly non-additive; for example, standalone benefits for course-department and enrollment-course-term do not sum to their measured pair benefit. All pair interactions, including adverse interactions, are retained in [`interactions.csv`](../../results/h/interactions.csv).

## Limitations

The data are synthetic, static, and free of production skew. Measurements are warm-cache, single-client, read-only results on one WSL2 machine; they do not represent concurrent production traffic or index write amplification. Only six candidates are exhaustively measurable—one-hot subset ILP does not scale to a large candidate catalog. Five timing repeats and three throughput cycles still expose host noise. Full-size, cold-cache, concurrent-reader/writer, update-cost, and sensitivity experiments are not run.
