# F — Mini-compiler and safe optimization

Status: **quick profile executed** on 2026-10-28. Full profile is **NOT RUN**. The implementation is dependency-light Python and uses a deliberately small language so every transformation can be inspected and checked.

## Language and compiler pipeline

The grammar supports assignment and `print` statements, integer literals and variables, parentheses, unary minus, and binary `+`, `-`, and `*` with conventional precedence. Example:

```text
a = 2 + 3 * 4;
b = -(a - 20);
print b + a;
```

Integers have unbounded mathematical semantics (Python `int`), so there is no overflow. Division is intentionally absent. Evaluation is deterministic and left-to-right. Expressions are pure; the ordered `print` values are the only observable result. Assignments are internal state, so an assignment that cannot reach a print is dead. Undefined variables are rejected during lowering and evaluation.

The implemented pipeline is:

```text
source → lexer → recursive-descent parser → AST evaluator
       → three-address IR → optimization passes → bytecode generator → VM
```

Tests and experiments compare AST output, original IR output, optimized IR output, and generated bytecode output. Before/after IR and bytecode are retained in [`ir_snapshots.json`](../../results/f/ir_snapshots.json).

## Four optimization passes

| Pass | Safety rule | Targeted measured effect |
|---|---|---:|
| Constant folding | Evaluate only binary operations with two literal operands | IR changed; output preserved |
| Constant propagation | Substitute a known constant until its variable is redefined | IR changed; output preserved |
| Dead-code elimination | Backward liveness from `PRINT`; expressions have no side effects | 3 → 2 instructions |
| Common-subexpression elimination | Reuse an available expression; invalidate on operand redefinition | 8 → 7 instructions |

All four passes changed their targeted IR fixture, and all four fixtures remained equivalent. The adverse reassignment case produces `(5, 13)` before and after optimization, demonstrating that CSE does not reuse `a+b` across an assignment to `a`.

## Discrete pass-order optimization

Pass order is an explicit discrete problem. Each of the four passes must occur exactly once. Exact subset dynamic programming explores reachable `(pass subset, IR)` states and lexicographically minimizes final instruction count and then encoded code bytes. Equivalent IR states are deduplicated. The training program is separate from the five measured benchmark programs to avoid selecting an order on the evaluation set.

The search explored 29 states and 42 transitions in 0.602 ms. The fixed order scored 5 instructions / 61 bytes on training. DP selected:

```text
CSE → constant propagation → constant folding → dead-code elimination
```

It scored 5 instructions / 56 bytes, an 8.2% code-size improvement at equal instruction count. Search candidates are in [`pass_order_search.csv`](../../results/f/pass_order_search.csv).

## Measured held-out results

Seven compile repeats and seven execution repeats were measured per program and strategy. Execution repeats ran 300 VM evaluations and report median time per program. Instance construction and artifact I/O were outside the timed regions.

| Strategy, summed over 5 programs | Instructions | Code bytes | Sum of median compile time | Sum of median execution time |
|---|---:|---:|---:|---:|
| Unoptimized | 27 | 317 | 0.269 ms | 6.696 µs |
| Fixed four-pass order | 15 | 162 | 0.334 ms | 3.664 µs |
| DP-selected training order | 17 | 191 | 0.359 ms | 3.729 µs |

The fixed order reduced instructions by 44.4%, code size by 48.9%, and summed median VM time by 45.3%, while summed compile time increased by 24.1%. These tiny timings are illustrative rather than performance guarantees.

The DP order improved its training objective but did **not** generalize best: the fixed order used two fewer held-out instructions and 29 fewer bytes. This negative result is retained rather than describing DP as universally superior. The minimal program also shows that optimization overhead can dominate a one-instruction result.

## Limitations

The language has no external input, branches, loops, functions, memory, division, or machine integer overflow. Generated code runs in a Python educational VM rather than native machine code. The five fixtures are small synthetic programs, and the learned order is sensitive to its training workload. Host scheduling noise is significant at microsecond scale; raw repeats are retained. Full profile was not run.
